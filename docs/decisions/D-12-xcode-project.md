# D-12 — The Xcode project is generated from a checked-in `project.yml`

*Taken in Sprint 0.*

## Decision

`Itchy.xcodeproj` is generated by XcodeGen from `project.yml` and is not
committed. `project.yml` is the source of truth for the app target, its two test
bundles, the scheme, and the generated `Info.plist`. `make project` regenerates;
`make open` regenerates and opens Xcode. XcodeGen is installed from Homebrew.

## Why

A `pbxproj` is roughly nine hundred lines of UUID-keyed references. It is
reviewable only by running it, it conflicts on almost every concurrent change,
and it is the one file in a project where a wrong edit produces a failure that
looks like a compiler problem. Every other piece of this project's
configuration is readable text with its reasoning attached, and there was no
good argument for the project definition being the exception.

The generated `Info.plist` follows from the same reasoning. Hand-maintaining it
would mean the bundle identifier, the deployment floor and `LSUIElement` each
had two definitions that were expected to agree.

## What this costs

Adding a file in Xcode does not add it to `project.yml`, so a new file needs a
regeneration before it is in the target. In practice files are created in the
editor and picked up by `sources: [App]` on the next generate, which is what
`make test` and `make coverage` both do first — but it is a real difference from
the usual workflow and worth knowing about rather than discovering.

It is also a build-time dependency, which sits next to D-4's prohibition on
third-party dependencies. D-4 is about what ships inside the application; a tool
that produces a project file at development time does not ship, link, or run in
the delivered binary, so it is outside that prohibition. Noting the distinction
here because the two could otherwise look contradictory later.

## Reversing this

If the regeneration step becomes more friction than the opacity was worth,
generate the project once, commit it, delete `project.yml`, and remove the
`project` prerequisite from the Makefile targets. Nothing else depends on the
choice.
